项目背景
FoneSquare 海外B2B二手手机交易平台需要一套内部管理后台，用于运营和销售团队对海外商家进行录入、查询和日常管理。MVP 阶段仅搭建 Web 管理后台。

解决方案

👥 角色权限模型

角色数据范围查看列表查看详情添加商家编辑商家分配销售导出
管理员全量✓✓✓✓✓✓
销售仅自己自己的自己的✓ 自动绑定✗✗✗
⚠️
销售添加商家规则：销售可添加商家，添加后该商家自动绑定到该销售名下，无需手动分配。后续管理员可在商家详情页调整所属销售。
数据权限：销售仅能查看和操作自己名下绑定的商家数据，不可访问其他销售或未分配的商家。

🔄 商家状态机

商家仅有两种业务状态：使用和停用。创建后默认为"使用"状态。不支持物理删除，通过"停用"处理。

stateDiagram-v2 s1 : 使用 s2 : 停用 [*] --> s1 : 创建商家 s1 --> s2 : 管理员停用 s2 --> s1 : 管理员启用
状态标签说明允许操作
使用使用商家正常运营，可下单交易编辑信息、分配销售、停用
停用停用商家已停用，不可交易，数据保留用于审计启用、查看

📊 角色与入口

登录后根据 OB 账号角色自动识别权限范围，不同角色进入不同视图。

flowchart LR A[OB 账号登录] --> B{角色识别} B -->|管理员| C[全量商家列表 + 全功能操作] B -->|销售| D[仅自己商家列表 + 受限操作]

📊 管理员操作流程

管理员拥有全量数据和全功能操作权限，包括添加、编辑、停用/启用、分配销售和导出。

flowchart TD L[商家列表] --> S[搜索+筛选+导出] L --> A[添加商家] L --> D[查看商家详情] A --> A1[填写基本信息+KYC] A1 --> A2[创建成功,状态:使用] D --> T1[基本信息 - 可编辑] D --> T2[KYC材料 - 可编辑] D --> T3[销售绑定 - 分配或更换] D --> T4[操作日志 - 全部记录] D --> OP[停用或启用]

📊 销售操作流程

销售仅能查看自己名下的商家。可添加商家（自动绑定自己），但不可编辑、分配销售或停用商家。

flowchart TD L[自己的商家列表] --> S[搜索+筛选] L --> A[添加商家,自动绑定自己] L --> D[查看商家详情] A --> A1[填写基本信息+KYC] A1 --> A2[创建成功,自动绑定] D --> T1[基本信息 - 仅查看] D --> T2[KYC材料 - 仅查看] D --> T4[操作日志 - 自己相关]

📊 添加商家业务流程

管理员和销售均可添加商家，差异在于绑定行为：销售添加自动绑定，管理员添加需手动分配。

flowchart TD START[进入添加商家页面] --> FILL[填写基本信息+KYC+企业信息] FILL --> CHECK{必填校验} CHECK -->|不通过| ERR[高亮缺失字段提示] ERR --> FILL CHECK -->|通过| SUBMIT[提交创建] SUBMIT --> ROLE{当前角色} ROLE -->|销售| BIND[自动绑定到当前销售] ROLE -->|管理员| UNASSIGN[未分配销售] BIND --> OK[创建成功,结果页] UNASSIGN --> OK

🔌 对外查询接口

海外商家管理后台需要对外提供商家信息查询能力，供国内订单/风控/支付等系统调用。本接口部署在海外服务，需认证鉴权和访问审计。

接口概述
用途
国内系统通过此接口获取海外商家基本信息，用于订单创建、风控校验等场景
部署位置
海外服务器
认证方式
内部服务间鉴权（Token / 签名验证），不对外公开
访问审计
所有查询请求记录调用方、时间、查询条件，用于合规审计

查询方式

查询条件匹配方式返回字段说明
海外商家ID精确匹配商家名称、类型、状态、脱敏联系方式、所在地区、国内商家ID最常用场景：国内系统通过映射ID查询商家信息
商家名称模糊匹配同上，支持分页返回运营查询场景，按名称关键词搜索
手机号精确匹配同上风控/客服场景，通过手机号定位商家
ℹ️
数据脱敏规则：接口返回的手机号、邮箱默认脱敏（如 +852 9***4567），仅特定权限的调用方可获取完整信息。证件号码、KYC照片等敏感信息不通过此接口返回。

🔄 海外-国内数据同步方案

为满足合规要求，商家完整数据（PII、KYC、证件）仅存储在海外服务器。但国内的订单、风控、支付等业务系统需要商家基本信息才能完成业务闭环。采用「海外主数据 + 国内镜像 + 双ID映射」架构。

整体架构

flowchart LR subgraph overseas[海外服务] A[商家管理后台] B[完整商家数据] C[对外查询接口] end subgraph domestic[国内服务] D[CS商家管理系统] E[镜像商家数据] F[订单+风控+支付] end A -->|创建+更新+状态变更| D F -->|查询海外商家详情| C F -->|使用国内商家ID| E

双ID映射关系

系统主键存储的对方ID数据范围
海外商家后台overseas_merchant_iddomestic_merchant_id（同步成功后回写）完整数据：基本信息 + KYC + 企业信息 + 证件照片
国内CS系统domestic_merchant_idoverseas_merchant_id脱敏摘要：名称、类型、状态、脱敏手机号、地区

同步规则

触发事件同步方向同步内容失败处理
海外创建商家海外 → 国内名称、类型、脱敏手机号、地区 → 国内创建镜像记录重试3次 → 进入异步队列 → 运营告警
海外编辑商家信息海外 → 国内同步可变字段（名称、手机号、地区）异步同步，失败不阻塞主流程
海外停用/启用商家海外 → 国内同步状态变更重试3次 → 运营告警（状态不一致影响交易）
国内需要商家详情国内 → 海外通过对外查询接口按需获取接口不可用时展示已同步的脱敏摘要信息

业务流程闭环

flowchart TD A[海外后台创建商家] --> B[生成海外商家ID] B --> C[同步请求国内CS系统] C --> D[国内生成国内商家ID] D --> E[记录双ID映射关系] E --> F[回写国内ID到海外记录] F --> G[同步完成] G --> H[国内订单系统创建订单] H --> I[使用国内商家ID] I --> J{需要海外商家详情} J -->|是| K[调用海外查询接口] J -->|否| L[使用已同步的脱敏摘要]
⚠️
关键注意事项：
1. 海外为唯一数据源（Source of Truth），国内不可直接修改商家信息
2. 证件号码、KYC照片等敏感数据不同步到国内，仅通过接口按需查询
3. 建议定期运行对账Job，比对海外和国内的商家数量及状态是否一致
4. ID策略建议使用UUID避免自增ID在两个系统间冲突

🔄 数据同步运营规则

同步与对账
同步时机
商家创建、信息编辑、状态变更时实时同步到国内CS系统
对账频率
每日凌晨自动对账，比对海外与国内商家总数、状态一致性
异常处理
同步失败时自动重试3次（间隔递增），超过后进入异步队列并发送运营告警
人工介入
对账发现不一致时，运营可在后台手动触发单条/批量重新同步

🔗 销售绑定规则

绑定规则
关系类型
一对多：一个销售可绑定多个商家，一个商家仅绑定一个销售
自动绑定
销售添加的商家自动绑定到该销售名下，无需手动分配
手动分配
管理员可在商家详情页为未分配的商家分配销售，或调整已有绑定
更换规则
仅管理员可更换销售绑定，更换后原销售立即失去该商家数据查看权限
未分配商家
管理员添加但未指定销售的商家，仅管理员可见

3KYC 是否对接第三方验证？MVP暂不对接，后台录入+人工审核。后续接入OCR乔谦
4OB角色如何配置？在OB系统分配admin/sales角色，后台通过Token中的role自动识别乔谦
5商家可以删除吗？不支持删除，通过"停用"处理，数据保留用于审计乔谦
6商家类型可以变更吗？创建后不可自助变更，需管理员操作并记录原因到操作日志乔谦
7证件照片存储在哪里？云OSS，后端返回加密URL。证件号码数据库脱敏存储乔谦
8商家数据为什么需要海外-国内双ID？合规要求商家PII数据（KYC、证件）仅存海外。国内订单/风控系统需要商家基本信息，因此在国内CS系统创建镜像记录并记录映射关系，国内业务使用国内ID闭环。乔谦
9国内系统如何获取海外商家完整信息？通过海外提供的对外查询接口，按需获取。支持按海外商家ID、名称、手机号查询。敏感信息（证件号、KYC照片）不通过此接口返回。乔谦
10同步失败怎么办？自动重试3次 → 进入异步队列 → 运营告警。每日自动对账，发现不一致可手动触发重新同步。创建类同步失败不阻塞海外操作，但国内暂时无法看到该商家。乔谦

📖 产品说明

页面概述

商家列表是后台的核心入口页面，运营和销售人员进入系统后默认展示此页。支持多条件组合筛选、排序和分页浏览，管理员可查看全量数据，销售仅可查看自己绑定的商家。

筛选条件

  • 商家名称：模糊搜索，支持中英文关键词
  • 商家类型：下拉选择，全部 / 买家 / 卖家
  • 状态：下拉选择，全部 / 使用 / 停用
  • 所属销售：下拉选择销售人员，仅管理员可见此筛选项。销售登录时自动隐藏此字段

表格字段

字段说明
ID系统自增唯一标识
商家名称公司全称或个人姓名，点击可进入详情
类型买家（青色标签）/ 卖家（紫色标签）
状态使用（绿色）/ 停用（灰色）
联系人/方式主要联系人姓名及手机号/邮箱
所属销售已绑定的销售名称，未分配显示灰色"未分配"
创建时间商家录入时间，默认倒序排列

交互规则

  • 默认按创建时间倒序，支持点击表头切换排序
  • 默认 10 条/页，支持 10/20/50 切换
  • 点击行或"查看"按钮进入商家详情页
  • "编辑"按钮仅管理员可见，销售角色隐藏
  • "导出"按钮仅管理员可见，导出当前筛选结果为 Excel
  • "添加商家"按钮管理员和销售均可见

📖 产品说明

页面概述

商家详情页是查看和管理单个商家完整信息的页面。通过 Tab 切换展示 4 个信息面板。页面顶部展示商家关键统计数据。

Tab 面板说明

Tab内容权限

📖 产品说明

页面概述

添加商家页面采用单页表单设计，一页展示全部录入字段（基本信息 + 身份认证 + 企业信息），便于运营/销售人员一目了然需要收集的完整信息。管理员和销售均可使用此功能。

角色差异

场景行为
管理员添加创建商家后，商家暂未绑定销售（所属销售为"未分配"）。管理员需在商家详情页手动分配销售。
销售添加创建商家后，系统自动将该商家绑定到当前销售名下。销售无需手动操作绑定。后续管理员可在商家详情页调整绑定关系。

表单分区说明

  • 基本信息区：商家类型（买家/卖家卡片选择）、商家名称、联系人、手机号、邮箱、所在地区、详细地址、备注
  • 身份认证区（KYC）：证件类型下拉、证件号码、证件姓名、有效期、证件照片上传（正面+背面+手持）
  • 企业信息区（选填）：企业名称、营业执照号、营业执照照片。填写后可获得更高交易额度

交互规则

  • 商家类型卡片点击切换选中状态，选中后有蓝色边框和背景高亮
  • 必填字段标红星，未填写时提交触发校验提示
  • 证件照片支持拖拽上传，上传后展示缩略图预览，可删除重新上传
  • 提交成功后展示结果页，包含商家 ID 和快捷操作按钮
  • 商家名称做唯一性校验，重复时前端实时提示

📖 产品说明

页面概述

销售分配总览页是管理员的全局视图，用于查看所有销售的商家绑定情况，快速定位未分配商家并进行分配。此页面仅管理员可见。

页面结构

  • 统计卡片：顶部 4 个统计卡片展示总商家数、已分配数、未分配数、销售人数
  • 未分配商家表：展示所有未绑定销售的商家，每行可点击"分配销售"按钮弹出 Modal
  • 销售绑定分布表：展示每个销售的绑定商家数量、使用/停用分布，点击"查看商家"跳转到该销售的商家列表

绑定机制说明

场景行为
销售添加商家商家自动绑定到该销售名下，不会出现在"未分配"列表中
管理员添加商家商家暂不绑定任何销售，出现在"未分配商家"列表中。管理员可在此页面或商家详情页分配
管理员更换销售通过商家详情页"销售绑定"Tab 操作。更换后原销售立即失去该商家数据权限

交互规则

  • 此页面仅管理员可见，销售角色左侧导航不展示"销售分配"入口
  • "分配销售"Modal 中下拉列表展示所有 role=sales 的 OB 账号
  • "查看商家"跳转到商家列表页，并自动填入该销售的筛选条件
  • 分配/更换操作均记入操作日志
